# Plan · Sala 04 · HUB clearnet en modo puente (§8) sobre `pub.escrivivir.co`

## Contexto

El pub `pub.escrivivir.co` corre Oasis **1.0.8** (upgrade cerrado 2026-09-12, journal
`devops/logs/deploy-history.jsonl`, `main` = `f98cb6f`). La release trae el **HUB
clearnet**: visor web de solo lectura del contenido público de los habitantes que han
activado *Clearnet* en su perfil (`docs/PUB/clearnet.md`). Hoy el pub arranca en modo
`server` (solo sbot) y el HUB está inerte.

**Decisiones del custodio (2026-09-13):**

- Estrategia: **proxy al backend del pub (§8) como puente**, no sidecar standalone.
  El sidecar queda como WP diferido con el análisis hecho (ver «Diferido»).
- Alcance: **paridad completa con upstream** (los 12 tipos), inherente al puente.
- Servicio: al ser proxy es necesariamente **proceso vivo tras Caddy**; el contenido
  vive en `/c/*` (rutas y enlaces absolutos del backend; Caddy no reescribe HTML).
- Sala: **Sala 04 · HUB**, puerta estática en **`/hub/`** (convención de
  `/hackeria/`, `/parlament/`, `/teatro/`) con tarjeta en el vestíbulo `/scriptorium/`.

### c) Por qué así (hechos verificados en `src/` 1.0.8 y en el repo)

- Modo `--public`: 403 a todo no-GET (`backend.js:11284`); `/c*` exige GET **antes**
  (`middleware.js:56`) → `POST /c` = **400**. `about.name/image` → «Redacted» sin
  `publicWebHosting`; «not accessible» es **HTTP 200** (`backend.js:6284-6294`).
- Host: `/c*` salta la validación; `/clearnet` (redirect) y `/qr/:feedId` **no** →
  `--allow-host=<hostname>` obligatorio. `OASIS_PUB_WEB_HOST` puede traer esquema
  (`pub/.env.local.example` = `http://localhost`) → sanear.
- Assets: el HUB inyecta su CSS inline (`clearnet_view.js:209-249`); solo carga
  `/assets/images/*` (logo, avatar por defecto) y `/qr/*`. `/assets/fanzine.css` es de
  la landing → proxyear **subrutas** de `/assets`, nunca `/assets/*`.
- `stripInternalAnchors` (`clearnet_view.js:103-121`) elimina anclas a rutas internas
  de Oasis: el HUB solo enlaza `/c*`, `/qr/*`, `/assets/*`.
- Dos procesos en un contenedor es el modo canónico upstream (`docs/devs/install.md`:
  «backend.js connects to the sbot through ssb-client over a local Unix socket»;
  `oasis.sh server` = sbot & + sleep 10 + `backend.js --public --no-open --host=0.0.0.0`).
  **R0**: `gui.js:13-16` hace `const { server } = require('../server/SSB_server')` y el
  getter (`SSB_server.js:251-255`) crea un sbot embebido si no existe → gate local
  obligatorio; plan B de 3 líneas listo.
- Primer arranque del backend: envía un **PM de bienvenida a sí mismo** si no existe
  `~/.ssb/oasis-first-contact` (`backend.js:11441-11484`) → sembrar el flag para que
  el HUB no escriba en L1.
- `/qr/:feedId` codifica `http://localhost:3000/...` fijo (`backend.js:537`):
  limitación upstream, se explica en la sala. `/c/blob/*` ya manda `immutable`.
- Feed del pub `@/snvahva…` → URLs con barras codificadas `/c/inhabitant/%40%2F…`;
  Caddy reenvía el URI crudo: primer curl de la verificación.
- VPS: layout `/opt/oasis-scriptorium/OASIS_PUB` sin git; Caddyfile bind-mounted
  **como fichero** (`./caddy/Caddyfile:/etc/caddy/Caddyfile:ro`) → subir **in place**
  (`cat >`), nunca por rename. Compose y Caddyfile vivos difieren del repo solo en
  comentarios; `site/index.html` idéntico; `site/scriptorium/index.html` vivo tiene
  el token público de PUBLIC_ROOM y una etiqueta de diagrama (TEATRO-PROTOCOL §6).
- `deploy-site.sh` = `rsync --checksum --delete` sin exclusiones (borraría
  `*.bak-teatro` de `site/`). Cambiar `docker-entrypoint.sh` invalida la capa
  `npm install` → rebuild completo (~3 GB; prune antes). Pub hoy: 91 MiB, 2,9 GB libres.

## Implementación (rama `wp/O46-hub-clearnet`)

### 1. `docker-entrypoint.sh` — modo nuevo `server-hub`, `server` intacto

- Helper `is_server_mode()` (`server|server-hub`) y usarlo en las tres condiciones
  `[ "$MODE" = "server" ]` (líneas ~468, 475, 488) para heredar «saltar IA».
- Helpers nuevos: `disable_ai_modules` (sed `aiMod`/`aiNavMod` → off sobre
  `$CURRENT_DIR/src/configs/oasis-config.json`, variable propia: **no** reutilizar
  `$CONFIG_FILE`, que `setup_ssb_config` pisa en la l.49, bug preexistente que no se
  arregla aquí), `hub_allow_host` (quita esquema/ruta/puerto de `OASIS_PUB_WEB_HOST`),
  `seed_first_contact_flag` (escribe el id del `secret` en `$SSB_PATH/oasis-first-contact`
  si no existe; idempotente, no bloquea), `wait_for_ssb_socket <pid>` (sondea
  `$SSB_PATH/socket` con `node -e net.connect`, timeout `OASIS_SSB_SOCKET_TIMEOUT` 60 s,
  falla si el sbot muere).
- Rama `"server-hub")`: `disable_ai_modules`; `seed_first_contact_flag`;
  `node SSB_server.js start &` → `wait_for_ssb_socket`; `node backend.js --public
  --no-open --host=0.0.0.0 --allow-host="$(hub_allow_host)" &`; `trap` TERM/INT que
  mata a ambos; `set +e; wait -n $SBOT $BACKEND; rc=$?`; matar al otro; `exit $rc`.
  **Sin `exec`**: con `exec` el sbot quedaría huérfano bajo `su` (PID 1) al morir el
  backend. Con el supervisor, muera quien muera el contenedor sale ≠ 0 y
  `restart: unless-stopped` lo relanza (paridad con hoy). Reinicio acoplado aceptado.
- Puerto 3000 solo en red Docker (no se publica). Healthcheck por socket **sin cambios**
  (así el rollback por `command: ["server"]` no queda `unhealthy`).

### 2. `pub/docker-compose.pub.yml` — servicio `oasis-pub`

`command: ["server-hub"]` (comentario: rollback `["server"]`) y
`OASIS_PUB_WEB_HOST: ${OASIS_PUB_WEB_HOST:-pub.escrivivir.co}` en `environment`.
Nada más. `mem_limit` **no** en el primer `up`: medir 10 min y 24 h con
`docker stats`, luego fijar `1.5×pico` (mín. 1024m, máx. 2048m) en un segundo `up`.

### 3. `pub/caddy/Caddyfile` — solo el vhost del pub (l.1-20)

```caddyfile
  header {
    X-Content-Type-Options nosniff
    X-Frame-Options DENY
    Referrer-Policy strict-origin-when-cross-origin
    defer          # un solo valor por cabecera también en respuestas proxyadas
  }

  @public path /public/*
  handle @public { reverse_proxy pub-panel-api:8787 }

  # HUB clearnet (UPGRADE-PROTOCOL §8, modo server-hub). Rutas absolutas del backend.
  # /assets/* NO entero: /assets/fanzine.css es de la landing.
  @hub path /c /c/* /clearnet /qr/* /assets/styles/* /assets/themes/* /assets/images/*
  handle @hub { reverse_proxy oasis-pub:3000 }

  handle { root * /srv/site  try_files {path} {path}/index.html /index.html  file_server }
```

Sin línea `@blob Cache-Control` (el backend ya la manda). Sin redirección
`/scriptorium/hub/c/*` (ruido: duplica URLs). Consecuencia consciente del `defer`:
`Referrer-Policy` en `/c*` pasa de `same-origin` a `strict-origin-when-cross-origin`;
la CSP del backend (`script-src 'none'`, `frame-ancestors 'none'`) no se toca.
Los 5 vhosts `*.scriptorium.escrivivir.co` (l.22-107) **no se tocan**.
