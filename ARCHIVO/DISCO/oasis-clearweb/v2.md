## Contexto

`pub.escrivivir.co` corre Oasis 1.0.8 en modo `server` (solo sbot). La v1 proponía activar el HUB
clearnet (`/c`) **dentro del contenedor del pub**: supervisor sbot+backend, entrypoint nuevo, rebuild
de imagen (~3 GB en el disco de sistema de 25 GB), reinicio acoplado y el riesgo R0 del getter de
`SSB_server.js`. El custodio pide replanificar con tres correcciones:

- **a)** El sbot del pub no se toca: ni proceso extra en su contenedor, ni entrypoint nuevo, ni rebuild.
- **b)** El HUB corre como **otra cuenta SSB** (nodo de soporte) que replica al pub y sirve `/c` desde
  su propio contenedor, con su propia replicación (su propio grafo y hops).
- **c)** El VPS tiene dos volúmenes: sistema **25 GB** (`/`, donde vive Docker) y datos **40 GB**
  (`/srv/oasis`, ext4 por UUID en fstab). Todo el estado y la caché del HUB van al grande, con una
  utilidad para medir y acotar su tamaño.

**Decisiones del custodio (2026-09-13, v2):** caché HTTP en disco **desde el día 1** (sidecar nginx
con `max_size`) · replicación del nodo de soporte a **hops 2** · Sala 04 en `/hub/` y paridad de los
12 tipos se mantienen de la v1 · identidad de la cuenta de soporte **`azofaifo-scriptorium-skin-bot-1`**
(convención `<nombre>-<tipo>-bot-<cardinal>`, D-O14; el `about` del paso 3 deriva de ahí).

### El hallazgo que hace posible la v2 sin tocar nada del pub

`backend.js` **no es un cliente puro**: `src/client/gui.js:12-16` hace
`const { server } = require('../server/SSB_server')` y el getter (`SSB_server.js:252-255`) **crea un
sbot embebido** si no existe; solo cae al socket unix si ese arranque falla por LOCK. Con un `~/.ssb`
propio, `node backend.js` **es un nodo SSB completo en un solo proceso**. El R0 de la v1 es aquí el
mecanismo, no el riesgo.

Las opciones CLI del backend se leen de env con prefijo `OASIS_` (`src/client/oasis_client.js:53-66`,
yargs `.env("OASIS")`): `OASIS_PUBLIC=true`, `OASIS_OPEN=false`, `OASIS_ALLOW_HOST=<host>`. El modo
`backend` del entrypoint (`docker-entrypoint.sh:521-524`) ejecuta `exec node backend.js --host 0.0.0.0`
y con `OASIS_SKIP_AI_MODEL=true` salta toda la IA. **Misma imagen, cero cambios en `Dockerfile`,
`docker-entrypoint.sh` y `src/`.**

`host` **debe ser `0.0.0.0`** (G2): el entrypoint lanza `backend.js --host 0.0.0.0`, `ssb_config.js` pasa `argv` a
minimist y `ssb-config/fix-connections` aborta con «conflicting connection settings for: net host» si difiere
(el contenedor no publica puertos, así que la exposición real no cambia).
Mismo `caps.shs` (ciclo 6); sin `external` (el HUB no se anuncia como pub). **Sin `seeds`** (retirado el
2026-09-13 en el VPS): el seed conectaba al pub al arrancar, ssb-gossip lo escribía en `gossip.json` y el
handler `POST /settings/invite/accept` (`backend.js:10736-10751`) corta con `alreadyFederated` si la clave
del invite ya está en `gossip.json` → el invite nunca se redimía. La persistencia de la conexión la deja
`invite.accept` + `hub-conn-fix.js` en `conn.json` (`key` + `autoconnect`), suficiente para reconectar
tras un reinicio (G3). El `secret` lo genera `ssb-keys` en el primer arranque dentro de
`/srv/oasis/oasis-hub/ssb-data` → **identidad nueva**, nunca copiada del pub.

### 4. `pub/config/hub/nginx.conf.template` — caché en disco acotada

```nginx

                 max_size=${HUB_CACHE_MAX_SIZE} inactive=7d use_temp_path=off;
limit_req_zone $http_x_forwarded_for zone=hub_req:10m rate=10r/s;   # todo llega desde la IP de Caddy

  listen 80;
  server_name _;
  resolver 127.0.0.11 valid=30s ipv6=off;
  set $hub_up http://${HUB_UPSTREAM};
  if ($request_method !~ ^(GET|HEAD)$) { return 405; }        # 2ª barrera; el backend ya 403ea

  location = /hub-cache-health { access_log off; return 200 "ok\n"; }

  proxy_hide_header X-Frame-Options;          # las fija Caddy (header global del vhost)
  proxy_hide_header X-Content-Type-Options;
  proxy_hide_header Referrer-Policy;
  proxy_hide_header Permissions-Policy;
  proxy_hide_header Set-Cookie;
  proxy_ignore_headers Set-Cookie;

  proxy_http_version 1.1;
  proxy_set_header Host $host;                # Caddy conserva el Host del cliente
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  proxy_set_header X-Forwarded-Proto https;
  proxy_set_header Connection "";
  proxy_connect_timeout 5s;
  proxy_read_timeout 40s;

  proxy_cache hub;
  proxy_cache_key "$scheme$host$request_uri";
  proxy_cache_lock on;
  proxy_cache_use_stale error timeout updating http_500 http_502 http_503 http_504;
  proxy_cache_background_update on;
  proxy_cache_valid 200 301 302 60s;
  proxy_cache_valid 404 30s;                  # caché negativa con caducidad (WP-O53)
  proxy_cache_valid 500 502 503 504 5s;

  location ^~ /c/blob/ {                      # immutable del backend; ausente = hasta 30 s de want

    proxy_cache_lock_timeout 35s;
    proxy_cache_lock_age 35s;
    proxy_cache_valid 200 30d;
    proxy_cache_valid 404 30s;
    proxy_pass $hub_up;                       # SIN URI: pasa $request_uri crudo (%2F intacto)

    limit_req zone=hub_req burst=20 nodelay;
    proxy_pass $hub_up;

  location ~ ^/assets/(styles|themes|images)/ {

    proxy_pass $hub_up;
  }
  location / { return 404; }
}
```

## Riesgos y decisiones abiertas

1. **Memoria** (el riesgo real): 4 GB para pub + HUB (backend completo + sbot embebido) + nginx +
   Caddy + panel. El pub no tiene `mem_limit`: un pico del HUB podría empujarlo al OOM-killer → el
   HUB arranca **con** `mem_limit` generoso y `--max-old-space-size`; ajuste a 24 h; `mem_limit` del
   pub → WP-O47.
2. **Comportamiento no verificable sin `node_modules`** (`ssb-invite-client.accept` → follow +
   `conn.remember`; ssb-conn 6 y `seeds`; reconexión tras reinicio): lo cubren G3 y el paso 3 por estado.
3. **Ventana `ssbLogStream.limit`** (20000): determina qué autores lista `/c`; coste de memoria y de
   `/c` (MISS). Ajustar tras medir; la caché de 60 s absorbe.
4. **Disco**: log replicado no podable (hops 2 lo acota; incluye `.box` privados ilegibles); blobs
   podables; caché acotada; `chown -R` de `blobs/` en cada arranque (lento sin `prune-blobs`). Tope
   duro → WP-O47.
5. **Indexing gate**: `/c` exacto no está en `allowDuringSync` (`backend.js:11305-11323`); tras un
   rebuild de índices sirve `indexingView` (200) y nginx lo cachea 60 s → `prune-cache`.
6. **200 que parecen 404**: `/c/inhabitant/<sin opt-in>` es 200 «not accessible» → se cachea 60 s como
   HTML (aceptable; documentado en la sala).
7. **Egress del HUB**: `updater.getRemoteVersion()` a code.03c8.net/github al arrancar
   (`middleware.js:183`, `updater.js`); inocuo, anotado.
8. QR a `localhost:3000` (por eso `/qr` no se expone) y «Redacted»/«not accessible» con 200: upstream;
   candidatos a WP-O83.
9. `robots.txt`: decidir `Disallow:` para `/c/blob/` (hoy `/robots.txt` devuelve la landing).
10. `deploy-site.sh --delete` sin exclusiones (igual que v1).
11. **Doble `Cache-Control`**: los HTML de `/c` no lo mandan → el navegador no cachea; si se quiere,
    `add_header Cache-Control "public, max-age=60"` en la location HTML.
